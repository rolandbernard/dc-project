
\subsection{Unique Column Combination Discovery} \label{ucc}

Unique column combination discovery has been performed on all tables for ths project using the Metanome HyUCC algorithm. This algorithm implements a version of the hybrid unique column discovery algorithm described in \cite{papenbrock2017hybrid}. The primary goal of this analysis is to identify possible keys in the dataset that can later be used as primary keys or regular unique constraints in the relational schema for \cref{relational}.


\subsubsection{\texorpdfstring{\inlinecode{bz_infrastructure_line} and \inlinecode{bz_infrastructure_node}}{bz\_infrastructure\_line and bz\_infrastructure\_node}}

In both \inlinecode{bz_infrastructure_line} and \inlinecode{bz_infrastructure_node} there are only three minimal unique column combinations, and all of them consist of only single columns. As such, these have already been identified in \cref{single}.
The minimal unique column combinations are \{\inlinecode{ogc_fid}\}, \{\inlinecode{gml_id}\}, and \{\inlinecode{objectid}\} for both of these tables.
All three of these are candidates for being a primary key in the relational schema. However, \inlinecode{gml_id} is a string that can be generated easily from \inlinecode{objectid}, which is an integer formatted as a real value, as explained in \cref{single}. \inlinecode{objectid} might be used elsewhere in data sets not used for this project as a foreign key, however, for this project \inlinecode{ogc_fid} seems like the best candidate for the primary key, as it is a dense integer identifier.
