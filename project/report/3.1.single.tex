
\subsection{Single Column and Correlation Analysis} \label{single}

Single column analysis has been performed for this project using both the YData Profiling Python library and the SCDP algorithm implementation for Metanome. The goal of this analysis is primarily to understand the type and distribution of data contained within the individual columns. As such it will influence for example the data type chosen for the corresponding attributes in the relational schema and ontology developed in \cref{relational} and \cref{ontology}. Some correlation analysis has also been performed as part of this step using the YData Profiling library. Below I include, in addition to some commentary about the results, also tables that include the most relevant information for each column of the various tables.

\Cref{tab:bz_infrastructure_line} shows the most important single column analysis results for each column of the \inlinecode{bz_infrastructure_line} table. The table contains a total of 47551 rows. We can operate that the table contains three columns that individually for a unique key, \inlinecode{ogc_fid}, \inlinecode{glm_id}, and \inlinecode{objectid}. \inlinecode{ogc_fid} is a sequentially increasing integer, going from 0 to 47551. Interestingly, \inlinecode{objectid} is stored as a real data type, with values such as "94188705.0", "94188707.0", or "94188708.0". However, all values are whole integers. The values of \inlinecode{glm_id} all follow the pattern \inlinecode{UrbanPlan-InfrastructurePlan-Network.<objectid>} where \inlinecode{<objectid>} is the integer value stored in the \inlinecode{objectid} column of the same tuple.
\inlinecode{istat_code}, \inlinecode{nda_link_de}, \inlinecode{nda_link_it}, \inlinecode{gem_text_d}, and \inlinecode{gem_text_i} all have 115 distinct values, indicating that they might contain related values. This relationship can also clearly be seen in the correlation matrix show in \cref{fig:bz_infrastructure_line_corr}. Manually inspecting \inlinecode{gem_text_d} reveals that it contains the names of municipalities, presumably the one the infrastructure line belongs to. \inlinecode{gem_text_i} contains the Italian name and \inlinecode{istat_code} some kind of identifier. \inlinecode{nda_link_de} and \inlinecode{nda_link_it} contain links that when followed lead to the Implementing rules to the land-use plan of the given municipality.
\inlinecode{code}, \inlinecode{bez_i}, and \inlinecode{bez_d} all have 11 distinct values. These values seem to indicate the type of infrastructure that is represented by this tuple, with the values in \inlinecode{bez_d} being the German name, those in \inlinecode{bez_i} the Italian name, and the values in \inlinecode{code} being an integer identifier of the type. Note that like with \inlinecode{objectid}, the values in \inlinecode{code} are represented as real numbers ending with ".0", meaning they all have integer values. The following are all possible values of \inlinecode{bez_d}: "Trinkwasserleitung", "Druckrohrleitung", "Abwasserleitung", "Schlammleitung", "Methangasleitung", "Hochspannungsleitung", "Mittelspannungsleitung", "Fernwärmeleitung", "Hochspannungsleitung - Bannstreifen", "Sonstige Leitungen", "Methangasleitung - Bannstreifen".
Finally, \inlinecode{geom} contains the geometry of the infrastructure line. Manual analysis reveals that the values are in the Well-Known Text format \cite{ISO_IEC_13249_3_2016} and all of them are of type \inlinecode{MULTILINESTRING}. \inlinecode{shape_len} seems to contain real values. Comparing them with the geometry in \inlinecode{geom} seems to indicate that \inlinecode{shape_len} might be the length of the infrastructure line.  \inlinecode{nda_text_de} and \inlinecode{nda_text_it} have a constant value of "Öffne" and "Apri" respectively. \inlinecode{codealt} and \inlinecode{blp} only contain missing values and are therefore not particularly interesting for this project.

\Cref{tab:bz_hazard_landslide} shows the single columns analysis results for the \inlinecode{bz_hazard_landslide} table. The table contains 23737 rows, no missing values in any of the columns, and, like the previously analyzed tables, there are three columns that contain different types of identifiers: \inlinecode{ogc_fid}, \inlinecode{gml_id}, and \inlinecode{objectif}. \inlinecode{ogc_fid} is still a dense integer identifier, while \inlinecode{objectid} is a real formatted sparse integer identifier. \inlinecode{gml_id} strictly follows the pattern \inlinecode{UrbanPlan-HazardZonePlan-Landslides.<objectid>} similar to what has been seen for the infrastructure tables.
The three columns \inlinecode{istat_code}, \inlinecode{name_i}, and \inlinecode{name_d} all have exactly 104 district values and perfect correlation, showing that these are related. Analysis of the values shows that these represent the municipality that contains the given hazard area. Interestingly, there is also \inlinecode{gem_id} which given the name could also represent the municipality, but it contains fewer distinct value. It can be seen from the data that actually there is a relationship between \inlinecode{gem_id} and \inlinecode{istat_code}, where \inlinecode{gem_id} is given by taking the last two decimal digits of the integer value of \inlinecode{istat_code}.
There are also three columns, \inlinecode{status_gzp}, \inlinecode{desc_i}, and \inlinecode{desc_d}, that contain only a constant value of respectively "1", "Approvato", and "Genehmigt".
Further, another three related columns, \inlinecode{code}, \inlinecode{pericolo}, and \inlinecode{gefahr} contain the danger expressed as one of four different levels. The four distinct values for \inlinecode{gefahr} are "Massenbewegung - Untersucht und nicht gefährlich", "Massenbewegung - Mittlere Gefahrenstufe (H2)", "Massenbewegung - Hohe Gefahrenstufe (H3)", and "Massenbewegung - Sehr hohe Gefahrenstufe (H4)". Looking at \cref{fig:bz_hazard_landslide_corr} we can also see that there exists a column \inlinecode{id_gp} that is highly correlated with the danger level related attributes. It contains integer values from 0 to 9 as well as the value "n", the meaning of which is however unclear.
There are also three variables, \inlinecode{id_process}, \inlinecode{processo}, and \inlinecode{prozess}, related to the type of landslide represented by the row. The five distinct values for \inlinecode{prozess} are "Sturz", "Massenbewegung", "Rutschung", "Hangmure", and "Einbruch". Note that for some rows these contain missing values.
Next, the table also contains information about the depth of the investigation performed in \inlinecode{id_gs}, \inlinecode{gradodistudio}, and \inlinecode{bearbeitungstiefe}, where all the distinct values for \inlinecode{bearbeitungstiefe} are "Mittlere (BT10)" and "Hoch (BT05)".
The \inlinecode{geom} variable, like in all the other tables contains the geometry in Well-Known Text Format. All the geometries in this table are of type \inlinecode{POLYGON}.
Finally, there are the columns \inlinecode{x_label} and \inlinecode{y_label} that contain real numbers. It is unclear what these value mean exactly, and they are uncorrelated to all other columns in the table.
